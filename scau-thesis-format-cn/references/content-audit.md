# 内容审查与回灌验收

本页用于“按文件规定检查内容”和“把真实内容稳定回灌到模板”。格式规则依据 `format-rules.md` 和 `scau-template-comments.md`；学术事实依据用户论文、实验记录、数据和已核实文献。二者不能互相替代。

## 1. 审查输入与证据

先确定本轮是草稿整理、装版还是最终提交；列出论文输入、任务书/学院补充文件、数据、图表、文献稿和模板版本。只有当前可读材料可以当作证据，不能根据标题猜测文件内容。

- 官方 2024 包按 manifest 校验，并给所用规则标 `verified_primary` 或 `repository_transcription_only`。即使所有文件哈希匹配，未经定位原文也不能把规则验证状态升为已复验。
- 用户的具体任务书、导师要求与正式学校规则发生差异时，记录文件、条款、适用范围和冲突，不静默选择。
- 源材料缺页、只有图片、内容被截断或正文在文本框/附件里时，记录未覆盖范围，继续完成能够核对的部分。
- 不自行补实验、数值、样本量、显著性、结论、参考文献字段、签名或作者元数据。缺失内容以定位问题报告，措辞调整保持原意。

## 2. 先运行只读结构与内容信号检查

无需 Word 或第三方库的 `.docx` 检查：

```bash
python scripts/inspect_thesis_content.py work/thesis_working.docx --output work/content-audit.json
```

脚本只读论文；定位是 `word/document.xml` 内从 1 开始的段落顺序，包含表格单元格，不是 Word 页码。输出 `sections`、`abstract_stats`、`keyword_stats`、`findings`、`rule_provenance` 和 `limitations`。

它覆盖：模块标签及重复候选、摘要边界和空摘要、中文摘要长度信号、中文关键词 3–5 个/分号/末尾标点、英文关键词分号/末尾标点及大小写候选、常见模板残留、内容控件占位、科学参考结构提示。中文摘要长度同时给汉字数、非空白可见字符数、英文词数，不冒充 Word 字数；300–600 来自批注 C29 的仓库摘录，口径或边界有疑问时人工确认。

当前脚本不完成参考文献双向匹配、数据与结论验证、中英文语义翻译核对、标题编号连续性、图片内文字、页眉页脚、脚注和页面布局检查。脚本退出成功仅表示报告生成成功，零 `confirmed` 问题仍可能有人工项和未覆盖内容。

## 3. 必须补做的内容审查

| 检查项 | 依据与方法 | 结论边界 |
| --- | --- | --- |
| 内容完成度 | 对照任务范围、模板模块和源稿；空模块、模板例句、占位名/题名、缺数据分别定位 | 标签存在不表示内容完成；最终提交占位不能因“本轮未处理”而豁免。附录/缩略词表缺失不自动报硬错。 |
| 摘要与正文 | 建立目的、对象/样本、方法、主要数值结果、结论逐项对照，中文摘要 C29 字数/不引文单独核对 | 不引入正文没有的结果，不扩大适用范围，不为满足字数删除必要限定条件。 |
| 中英文对应 | 逐项对照题名、姓名/单位、摘要的对象/方法/结果/结论、关键词含义；保护拉丁名和标准缩写 | 英文语法可修，事实差异必须按源稿核对，不能直接用大写规则判断翻译正确。无证据时不增加英文词数阈值。 |
| 研究范围与论证 | 题名、研究目标、方法、结果、讨论、结论互相对应；定位 unsupported、相互矛盾或遗漏的链条 | 属学术内容人工检查。四章科学结构是参考，不强迫其他专业换章名。 |
| 数据与统计 | 按用户提供数据核对数值、样本量、单位、组别、误差指标、统计方法与图表/正文一致；核对显著性说明 | 未给原始数据时只能查论文内部一致性，不能声称验证实验真实性或统计正确性。 |
| 图表及正文提及 | 列正文图/表/公式及附录各自序列，对照实际对象、正文引用、题名、注释、分图标签、来源 | 图题、表题计数不是对象存在证明；图片文字和跨页需视觉核对。不要将附录 A1 并入正文连续编号。 |
| 文内—文后匹配 | 抽取正文引用键（第一作者、年份、a/b/c），与文后条目双向核对；区分叙述式引用、多源括号引用和重复引用 | 列出引用缺条目、条目未引用、同键冲突、年份/作者不一致；模糊姓名、机构作者和同年多篇人工确认。不得自动删除真实但未识别的条目。 |
| 文献字段和真实性 | 按 PDF 相应类型核对作者、题名、期刊/出版方、年份、期卷/页码、DOI/URL等；需外部核实时使用权威原文 | 格式齐全不等于文献真实；缺字段不能编造。中文/外文 grouping 由 C121 支持，具体语言次序和姓氏排序需核 PDF 原文。 |
| 术语与单位 | 首次定义、缩写/全称、对象名称、单位量纲、符号、时态等全文对照 | 单位转换只在已确认语义下进行，不能统一替换同形异义缩写。 |
| 声明和引用来源 | 对照声明原文、用户真实元数据、图表来源与著作权说明 | 不生成签名，不对真实性或原创性作无证据保证；不把通用合规建议当学校新增条款。 |

记录每项的源材料位置和论文位置。既可利用搜索/提取加速，也要区分“搜索未命中”与“确认不存在”。正文多种引用形式、扫描表格和文本框不能只靠一个正则判缺失。

## 4. 现有审查工具的覆盖范围

| 工具 | 实际覆盖 | 不能据此宣称 |
| --- | --- | --- |
| `inspect_thesis_content.py` | 跨平台可见 DOCX 文本、模块、摘要/关键词、占位和来源哈希状态 | 事实正确、完整文献匹配、全文语言正确、页面合规或官方原文已逐条复验。 |
| `inspect_word_report.py` | Windows Word 统计、模块信号、标题/题注数量与占位候选 | 标签表示模块完成；每个计数都等于真实对象数量；内容完整或学校合规。 |
| `inspect_word_format_signatures.py` | Windows Word 字符格式、部分标签/正文边界、目录特殊项和字体；正文布局、表格、排序等信号，具体覆盖随报告而定 | 样本/主要字符格式代表所有字符；排序算法证明学校语言次序；非加粗项必须禁止加粗；没有显式分页符就是页面违规。 |
| `inspect_figure_layout.py` + PDF/页面图 | 图文页映射、顺序、跨页候选和视觉检查证据 | 自动映射已证明图内信息正确或可读；所有复杂浮动对象都被准确匹配。 |

各报告的 `confirmed` 仅按该字段的观察范围解释。内容核对、规则复验、字体抽样与页面确认需分别写出状态，不用一个总状态掩盖缺口。

## 5. 回灌前：先生成可核对的内容清单

为每个待插入模块准备一个记录，至少包含：稳定 `content_id`、源文件/位置、目标章节/锚点、内容类型、原文或资产路径、状态（已核对/缺材料）、预期数量和关键核对值。前置模块、章节、图表、文献使用各自现有 metadata/manifest 入口；不要为此另起不兼容格式。

- 先验证文件存在、标记唯一、章层级正确、锚点只出现一次、目标确属同版模板；固定段落编号只能在模板锚点检查通过后使用。
- 文本、图、表、参考文献分别走相应插入脚本，明确本轮是替换还是追加；同一 manifest 不应因重跑重复插入。
- 保留原稿和带批注工作副本。批量改内容关闭修订记录；是否接受已有修订按任务范围处理，不用修订删除真实内容。
- 源稿未完成的模块继续标占位，最终提交阶段将其列为未完成项。不得用模板示例冒充真实正文。

## 6. 回灌后：检查内容守恒与变更合理性

回灌前后按内容清单核对每个模块：

1. 完整性：预期章节/段落/图表/文献数量，首尾文本和目标锚点，是否丢段、重复、截断、误入目录或表格。
2. 关键值：姓名/学号/日期、研究对象、样本量、组别、数值、单位、公式、引文作者/年份和图表题名；未经授权不能改变。
3. 结构：标题层级与序号、图表正文及附录独立序列、文内提及与实际对象、文后对应项。
4. 局部格式：标签/内容、题名/正文边界、图/题注/注释顺序、表题/表/表注、正文/文后字体；允许空白格式变化，不能将格式归一化当内容等价。
5. 页面：一次导出/渲染，检查本轮涉及页面和相邻页；最终提交检查全篇。字段刷新后再次核对目录特殊条目及页码。

大批量回灌按一组相关内容操作一次保存、一次导出/审查；局部改动优先复验变更模块及依赖项。来源、结构或关键值不匹配时回到相关插入层修复，不对整篇反复全局替换。使用最新输出作为后续输入，并记录输入/输出路径和每轮变更。

## 7. 交付报告

沿用脚本 schema 时，问题字段为 `rule_id`、`status`、`severity`、`category`、`source`、`location`、`observed`、`expected`、`note`；`source` 内包含 `rule_strength`、`rule_verification`、文件及批注 ID。人工补做的检查采用同样结构并加覆盖范围、源材料位置、修复/复查状态。不要把 XML 段落编号写成 PDF 页码。

交付说明应区分：已确认并修复的问题；符合模板默认值的项；仍有内容缺失/占位的模块；待人工或原始文件复验的项；未覆盖的媒体/页面。只有本轮范围内的内容和版式都完成且没有未解决的必需项，才可说“本轮已验收”；没有完整规则和页面证据不能宣布“学校全篇合规”。
